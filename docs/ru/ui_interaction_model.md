# Модель взаимодействия UI MeetingAgent

Статус: предложение на утверждение владельцем в issue [#237](https://github.com/Anatoliy-Sysoev/MeetingAgent/issues/237). Документ и макеты не изменяют production UI.

## Граница продуктов и навигация

MeetingAgent и Project Knowledge Bot остаются отдельными продуктами в одном локальном runtime:

| Поверхность | Целевой маршрут | Назначение |
| --- | --- | --- |
| Реестр встреч | `/MeetingAgent` | Поиск, фильтрация и открытие карточек |
| Создание встречи | `/MeetingAgent/new` | Загрузка медиа или live-карточка без файла |
| Монитор обработки | `/MeetingAgent/processing` | Наблюдение за единственной активной задачей и восстановление |
| Workspace встречи | `/meetings/{meeting_id}/workspace` | Работа с одной встречей и её доказательствами |
| Project Knowledge Bot | `/ui` | Поиск и чат по отдельному проектному корпусу |
| Администрирование | `/admin` | Пользователи и роли для администратора |

Первые четыре маршрута задают целевую информационную архитектуру. Сейчас реализованы только `/MeetingAgent` и существующий Workspace. До утверждения макетов production-шаблоны и маршруты не меняются.

## Иерархия поверхностей

### Реестр

Реестр является главным экраном. Это плотная таблица с поиском, фильтрами периода/статуса, одной полосой активной обработки и действиями строки. Статус, прогресс pipeline и доступные результаты видны без открытия встречи. Загрузка и live-создание начинаются одной командой `Новая встреча`.

### Загрузка и live-создание

Один мастер из трёх шагов обслуживает оба типа источника:

1. источник и сведения о встрече;
2. профиль обработки и ASR-движок;
3. preflight-сводка и явное подтверждение.

Загрузка принимает поддерживаемые локальные медиа и предлагает только транскрипт, подготовку для Q&A или полный pipeline. Live-создание не придумывает медиафайл: создаётся карточка, затем в Workspace запускается MIC/SYS.

### Монитор обработки

Монитор показывает одну durable job/pipeline, восемь последовательных стадий, текущую дочернюю стадию, ограниченные public-safe события, отмену и retry/resume. Готовность приходит из API; браузер не угадывает её по именам файлов.

### Workspace

Workspace использует стабильные вкладки задач вместо одной длинной колонки панелей:

| Вкладка | Основное содержимое | Контекстная панель |
| --- | --- | --- |
| Обзор | Метаданные, статус, участники и результаты | Готовность и последние ошибки |
| Транскрипт | Плеер и реплики с таймкодами | Сопоставление спикеров и источники |
| Артефакты | Summary, протокол, решения, задачи, риски, вопросы | Confidence и `needs_review` |
| Вопросы | Поиск по встрече и grounded Q&A | Точные ссылки на сегменты |
| Live | MIC/SYS и единая MIX-хронология | Готовность источника, предупреждения, offline refinement |
| Обработка | Стадии pipeline и текущая job | Retry/resume/cancel |

Плеер остаётся доступен при переходах между транскриптом, артефактами и Q&A. Клик по цитате открывает вкладку транскрипта, перематывает на точный `segment_id`/таймкод и выделяет реплику.

## Карта состояний API

UI должен показывать устойчивые продуктовые состояния, а не сырой JSON или локальные пути.

| API-поверхность | Успех и пустое состояние | Блокировки/ошибки | Отображение в UI |
| --- | --- | --- | --- |
| `GET /auth/me` | Пользователь и рассчитанные permissions | `401` нет сессии | Auth-бейдж; форма входа с сохранением целевой страницы |
| `POST /auth/local/login` | Сессия создана | `401` неверные данные, `429` throttle | Общая ошибка входа или ограниченный таймер повтора |
| `GET /auth/csrf` | Токен доступен только в памяти | `401`, `403`, `409` | Не выполнять write; обновить auth-state; не сохранять токен |
| `GET /meetings` | Строки; `items=[]` пустой реестр; ограниченные `errors[]` | `401`, `403`, `5xx` | Skeleton, действие для пустого списка, partial-warning или retry |
| `POST /meetings/ingest` | `201` карточка создана | `409` дубль, `413` лимит, `422` невалидно, `503` занято, `500` сбой | Прогресс; ссылка на дубль; полевая/preflight ошибка |
| `POST /meetings/live` | `201` live-карточка | `422` невалидно, `503` занято | Открыть Workspace; при ошибке сохранить введённые сведения |
| `GET /meetings/{id}` | Шапка и public-safe метаданные | `404`, `422` битая карточка | Not-found или ограниченное состояние восстановления |
| GET транскрипта/медиа/артефактов | Контент; пустые списки артефактов/медиа | `404`, `413`, `415`, `422` | Пустая вкладка, превышение лимита, альтернатива preview/download |
| GET/PUT спикеров | Labels и mapping | нет labels, `403`, `422` | Пустое состояние; viewer read-only; editor видит inline validation |
| `GET .../pipeline/readiness` | `done`, `ready`, `ready_for_retry`, `blocked` | `404`, `503` | Строки используют состояние/причину сервера; Start не угадывается |
| POST стадии/pipeline | `202` и durable `job_id` | `409` конфликт, `422` preflight, `503` store | Poll по ID; блокировка конфликтующих действий; retryable причина |
| `GET .../jobs/{job_id}` | `starting`, `running`, `completed`, `failed`, `cancelled`, `orphaned` | `404` ID потерян, `503` store | Poll точного ID; terminal summary; явное orphan recovery |
| `GET /meetings/{id}/live/preflight`, `/live/sessions*` | available; `starting`, `running`, `stopping`, `completed` | unavailable reason, `409`, `422`, `503`, `failed`, `stale` | Готовность по источнику; graceful stop; сохранение draft/warnings |
| `GET /meetings/{id}/live/timeline`, `GET/POST /live/refinement` | пустые или ограниченные MIC/SYS/MIX events; `draft`, `refining`, `final`, `failed` | нет draft, конфликт live/offline, preflight failure | Единый диалог; явный resume/force; draft не индексируется |
| `POST /meetings/{id}/search` | Результаты semantic/lexical; пустой список | индекс недоступен или request failure | Empty evidence; retrieval-mode; точный переход к реплике |
| `POST /meetings/{id}/chat` | `answered` с цитатами | `no_context`, `llm_unavailable`, `llm_error`, `no_answer` | Управляемое объяснение; обрывок не показывается как ответ |

Глобальная обработка единообразна: `401` запрашивает вход, `403` различает права и устаревший CSRF, `404` не раскрывает скрытую карточку, `409` означает конфликт workflow, `422` исправляется пользователем/preflight, `429` означает throttle, `5xx/503` предлагает повтор с ограниченным path-free сообщением.

## Видимость по ролям

| Возможность | Viewer | Editor | Admin |
| --- | :---: | :---: | :---: |
| Реестр, карточка, транскрипт, артефакты, поиск/Q&A | да | да | да |
| Upload/live и управление pipeline | нет | да | да |
| Speaker mapping и редактируемые артефакты | нет | да | да |
| Пользователи и роли | нет | нет | да |

Machine bearer token является сервисным credential и не отображается как browser-role. Скрытие контролов дублируется серверным RBAC; видимость не заменяет авторизацию.

## Responsive и accessibility

- Desktop использует постоянную product-навигацию, полноширинную таблицу и двухколоночный Workspace.
- Ниже 700 px таблица превращается в подписанные записи, навигация уходит вниз, Workspace показывает одну рабочую область за раз.
- Обязательных hover-only действий нет. Все команды — native button/link/input/select.
- Фокус всегда видим; первая клавиатурная цель — skip-link. В боковой навигации работают стрелки.
- Динамический статус использует `role=status`/`aria-live`, ошибки — `role=alert`.
- Viewer не видит write-кнопки, но сохраняет контекст и объяснения.
- Размер шрифта не зависит от viewport; на узком экране контролы не ниже 42 px.
- Запрещены inline handlers/styles, persistent browser credentials и сырые пути файловой системы.

## Граница утверждения

Утверждение документа означает, что навигация, иерархия, responsive-поведение и карта состояний становятся контрактом для отдельных production-задач. Оно не утверждает миграцию на новый framework, изменение backend/API или декоративные доработки вне описанных workflow.
