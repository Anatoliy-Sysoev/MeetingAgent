# Восстановление Whisper после сбоя

Новые запуски `22_transcribe_meeting.py --engine faster-whisper` сохраняют
завершённые блоки аудио в локальной папке `transcript/_whisper/` карточки.
Модель загружается один раз; начальный размер блока — 120 секунд исходного
аудио (`--whisper-block-seconds`, диапазон 1–600). Пустой блок также сохраняется.

При `--resume` повторно обрабатывается только незавершённый блок и следующие
за ним. Проверяются SHA-256 исходного файла, модель, настройки, версии ASR
библиотек, hashes и непрерывность блоков. При несовместимости нужен явный
`--force`, который создаёт новую generation, сохраняя предыдущую локально.
Checkpoint не переносит текст в `segments.jsonl`, пока распознавание не закончено.

```powershell
python scripts/22_transcribe_meeting.py --meeting-dir meetings/example --engine faster-whisper --resume
python scripts/22_transcribe_meeting.py --meeting-dir meetings/example --engine faster-whisper --force
```

`transcript/transcription_state.json` отмечает начатую и завершённую публикацию.
Пока обязательные экспорты и report не опубликованы, готовность transcribe и
запуск downstream блокируются. Повтор после сбоя экспорта использует ASR-блоки
без повторной загрузки модели. Старые карточки без marker читаются совместимо.

Размер возможной повторной работы — один блок аудио; время вычисления зависит
от оборудования. Паузы и VAD не сжимают абсолютную временную шкалу встречи.
На границах независимых блоков возможны отличия текста от непрерывного прохода;
побуквенное совпадение не гарантируется. Сравнение качества на русской речи и
реальный smoke вынесены в #329. У существующего запущенного worker checkpoints
не появятся автоматически: ему требуется завершиться, новый код работает для
следующих запусков. Повторный запуск API сам по себе не запускает ASR.

Checkpoints, audio, transcripts и private runtime reports не коммитятся.
Задачи: #325–#329; существующий контракт retry связан с #323.

UI показывает обработанный и сохранённый проценты отдельно. После сбоя в
Workspace доступны «Продолжить транскрибацию» и «Начать транскрибацию заново».
Readiness, registry и job DTO содержат только ограниченный public-safe recovery
summary; полная проверка SHA-256 и параметров выполняется worker preflight.
API быстро проверяет метаданные исходного файла и сохранённую границу, не
перечитывая весь транскрипт при каждом polling. При изменённом исходнике или
битой контрольной точке продолжение блокируется. ETA при resume вычисляется
по обработанным секундам и времени текущей попытки; простой не учитывается.

## Проверки аварийного восстановления

```powershell
python -m pytest tests/asu_june_bot/e2e/test_asr_crash_recovery.py -q
```

Тест запускает отдельный Python worker с реальными CLI, checkpoint storage и
экспортами, но детерминированной моделью: завершает процесс в середине второго
блока и проверяет пропуск первого блока при resume. Отдельно проверяются сбой
после экспорта, повтор без ASR, force generation и read-only dry-run.

Реальный ASR smoke включается явно, когда нет другого тяжёлого задания:

```powershell
$env:MEETINGAGENT_ASR_SMOKE_WAV = "<локальный WAV с русской речью>"
$env:MEETINGAGENT_ASR_SMOKE_MODEL = "large-v3-turbo"
python -m pytest tests/asu_june_bot/e2e/test_asr_real_smoke.py -q
```

Нужен WAV mono/PCM16/16 kHz длительностью 61–180 секунд и установленная модель.
Тест проверяет реальные multi-block outputs и повтор по кэшу. Качество текста
на границах требует прослушивания; автоматический тест не заменяет разметку.
При разработке #329 реальный smoke не запускался одновременно с рабочим ASR;
без переменной окружения он явно skipped. До rollout требуется этот прогон и
ручная проверка границ. Запущенный старый worker остаётся без checkpoints.
